# Roadmap

Work planned for the theme, ordered by priority. Items combine three sources: the 2026-07-08 audit of v4.5.2 plus the GitHub issue backlog, the 2026-10-09 audit against `main` at `b9dc62f` (v5.2.0), and the 2026-10-12 agent-visibility audit. When you finish an item on a branch, check it off here in the same PR. Completed work moves to [Done](#done) with its commit or release.

Priority key:

- **P1**: broken behavior, security, or accessibility failure. Fix next.
- **P2**: incorrect or fragile, but there is a workaround or the impact is limited.
- **P3**: cleanup, consistency, maintainability.

## P1: Bugs, security, accessibility

- [ ] **Unescaped subtitle output (stored XSS).** `ucsc_post_subtitle()` concatenates `get_field( 'subtitle-copy' )` into markup without escaping ([functions.php:336-341](functions.php#L336-L341)). An Author-role user can store `<script>` in the field. Wrap it in `esc_html()`.
- [ ] **Empty subtitle renders when the field is unset.** `get_field()` returns `null` for posts that never saved the field, and `null !== ''` is true, so an empty `.post-subtitle` div is appended. `$subtitle` is also undefined when ACF is inactive, and the function declares an unused `global $post` ([functions.php:324-331](functions.php#L324-L331)). Initialize `$subtitle = ''` and test with `! empty()`. Check the block name before calling `get_field()`: this filter — and `ucsc_post_author_link()` — runs on every block of every page.
- [ ] **Plugin-rendered pages reference template parts that don't exist.** `header-plugin.php` renders `ucsc-header`, `ucsc-footer`, and `content-plugin` ([header-plugin.php:15-17](header-plugin.php#L15-L17)). None of them are in `parts/`. Logged-in users see "Template part has been deleted or is unavailable". `$GLOBALS['ucsc_plugin_content']` is assigned and never used. Render `header`/`footer` with the same wrappers the block templates use (`header-region`, `breadcrumbs-region`, `footer-region`).
- [ ] **Mobile nav throws on plugin-rendered pages.** `initMainNav()` caches `.header-region` as the sticky header. `header-plugin.php` doesn't output that class, so `IntersectionObserver.observe(null)` throws inside `hideMenu()` and nav init stops ([src/js/components/main-nav.js:171](src/js/components/main-nav.js#L171), [:146](src/js/components/main-nav.js#L146), [:100](src/js/components/main-nav.js#L100)). More generally, `main-nav.js` calls methods on unchecked `querySelector()` results, so one missing element stops all nav JS. Guard the observer and query calls, and fix the wrapper as described in the previous item.
- [ ] **Sidebar navigation JS crashes when the current page is a top-level item.** `currentItem.closest( 'li.wp-block-navigation-submenu' )` returns `null` for a top-level `.current-menu-item`, so the `querySelector` call throws. `bindEvents()` and `fixAriaAttributes()` then never run ([src/js/block-patterns/sidebar-with-navigation.js:140-141](src/js/block-patterns/sidebar-with-navigation.js#L140-L141)). `init()` also calls `initBlockOnPageLoad()` a second time with no argument ([:153](src/js/block-patterns/sidebar-with-navigation.js#L153)). Add a null guard and remove the redundant call.
- [ ] **Nested `<main>` landmarks on archive, category, and blog pages.** `parts/post-query.html` sets `"tagName":"main"` on the Query block ([parts/post-query.html:1](parts/post-query.html#L1)). It is placed inside templates whose wrapper group is already `<main>` (`archive.html`, `category.html`, `home.html`). Change the Query `tagName` to `div` or `section`. Pairs with "Article semantics and content boundaries" under agent visibility.
- [ ] **Footer navigation is hardcoded to database IDs.** `wp:navigation {"ref":1938}`, `1942`, and `1945` ([parts/site-footer.html:8-16](parts/site-footer.html#L8-L16)) only exist on one site. Every other install renders empty or fallback menus. Footer social links point to relative URLs (`"url":"twitter.com"`), which resolve against the current site. Replace them with real URLs or remove them, and remove the hardcoded `ref`s so editors choose menus per site.
- [ ] **Core block patterns are not actually removed.** `remove_theme_support( 'core-block-patterns' )` runs on `init` priority 10 ([lib/blocks.php:9](lib/blocks.php#L9)). Core's `_register_core_block_patterns_and_categories` is hooked to `init` priority 10 earlier, from `default-filters.php`, so core patterns are already registered by then. Move the call to `after_setup_theme`. The workaround below it uses `has_block()`, which inspects post content, not the pattern registry, so it never fires. One slug also has a trailing space ([lib/blocks.php:12-17](lib/blocks.php#L12-L17)). Delete the workaround once the hook is fixed.
- [ ] **The main nav toggle has no accessible state.** The hamburger `<button>` has no text and no `aria-label` until JS runs, and it never gets `aria-expanded` or `aria-controls` ([blocks/main-nav/index.php:1-5](blocks/main-nav/index.php#L1-L5)). The same applies to the JS-generated submenu toggles ([main-nav.js:249](src/js/components/main-nav.js#L249)), which also need `type="button"`. The `<nav>` has no `aria-label`, which makes it ambiguous next to the Truss header nav. Add a server-rendered label plus `aria-expanded`/`aria-controls`, update them in `showMenu()`/`hideMenu()`/`activateMenuItem()`, close on Escape, and move focus into the open menu and back to the toggle on close. Related tracker items: [issue 359](https://github.com/ucsc/ucsc-2022/issues/359) (header z-index), [issue 358](https://github.com/ucsc/ucsc-2022/issues/358) (hover state), [issue 325](https://github.com/ucsc/ucsc-2022/issues/325) (44px targets), [issue 317](https://github.com/ucsc/ucsc-2022/issues/317) (ribbon contrast), [issue 332](https://github.com/ucsc/ucsc-2022/issues/332) (CLS), [issue 338](https://github.com/ucsc/ucsc-2022/issues/338)/[issue 339](https://github.com/ucsc/ucsc-2022/issues/339) (sidebar toggles).
- [ ] **Mobile menu Phase 2.** Phase 1 (v5.0.0) fixed the deadlocks; [issue 302](https://github.com/ucsc/ucsc-2022/issues/302) (toggle overlaps header content) is still open and the state machine still depends on `transitionend`. Make the open panel a fixed overlay anchored to the viewport (`position: fixed; overflow-y: auto; overscroll-behavior: contain`) so its height needs no JS; replace `src/js/utils/body-lock.js` with `html.main-nav--is-open { overflow: hidden }`; animate `transform`/`opacity` instead of `height` so interrupted animations can't break state; replace the resize chain with one `matchMedia('(min-width: 1060px)')` listener; fold in the toggle-accessibility item above. Test on iOS Safari (long menus, mid-page scroll, double-tap, rotation), narrow Firefox, keyboard only, and VoiceOver.
- [ ] **Breadcrumbs structured data fails Google validation** ([issue 330](https://github.com/ucsc/ucsc-2022/issues/330)). `itemListElement` is missing the required `position` field in the microdata printed by the theme's breadcrumbs (`justintadlock/hybrid-breadcrumbs`, `Trail::render()` in `functions.php`). On news.ucsc.edu, Yoast's breadcrumb JSON-LD already includes `position`, and the checked pages carried no theme microdata, so the error likely comes from pages that use the theme's breadcrumbs block. Add `position`, or drop the microdata when Yoast is active so there's one breadcrumb source.

## P2: Correctness and fragility

### theme.json and presets

- [ ] **The minimum WordPress version is wrong everywhere.** theme.json v3 requires WP 6.6. `style.css` says `Requires at least: 6.0`, `readme.txt` says `5.8`, and `README.md` says `6.7`. The PHP minimum is also inconsistent (7.4 / 7.0 / ">8.0"). Choose one supported floor and set it in all three files. `readme.txt` is the untouched starter template ("Theme Name", "Short description…"). Fill it in or delete it.
- [ ] **Undefined CSS custom properties.** These are referenced but never defined, so the declarations fall back to `inherit` or the initial value:
  - `--wp--custom--color--black`: core/heading text color ([theme.json:466](theme.json#L466))
  - `--wp--custom--color--link-decoration` ([src/scss/elements/\_links.scss:3](src/scss/elements/_links.scss#L3))
  - `--wp--custom--color--default-text`, `--wp--custom--color--light-gray` ([src/scss/pages/\_posts-pages.scss:4,23,30](src/scss/pages/_posts-pages.scss#L4))

  Point them at `--wp--preset--color--*` or define them under `settings.custom.color`.
- [ ] **Undefined font-size slugs in markup.** `"fontSize":"medium"` ([templates/404.html:16](templates/404.html#L16), `patterns/media-with-text-fixed-width.php`) and `"fontSize":"xx-large"` (`patterns/example-page-home.php`, `patterns/example-page-topic.php`) output `has-medium-font-size` / `has-xx-large-font-size` classes that have no matching CSS. Map them to existing slugs (`one`…`eight`).
- [ ] **The `ucsc/image/sizes` filter has no effect.** `register_sizes()` loops over `$this->sizes` directly, and the filtered result from `get_sizes()` is discarded ([lib/image_sizes.php:58-62](lib/image_sizes.php#L58-L62), [functions.php:418](functions.php#L418)). Loop over `$this->get_sizes()` and remove the stray call.
- [ ] **Duplicate template.** `templates/page-no-title-with-breadcrumbs.html` is byte-identical to `page-no-title.html`, which already includes breadcrumbs, and it isn't declared in `customTemplates`. PR 404 already removed it from the template picker; now delete it, or make the two templates differ and declare both. Announce the removal ([issue 357](https://github.com/ucsc/ucsc-2022/issues/357), [issue 386](https://github.com/ucsc/ucsc-2022/issues/386)).
- [ ] **Legacy layout attributes.** `"layout":{"inherit":true}` was superseded by `{"type":"constrained"}` in WP 6.1. It still appears in `templates/404.html`, `archive.html`, `category.html`, `home.html`, `parts/site-footer.html`, and `parts/site-header.html`. `parts/post-query.html` also uses the deprecated Query `displayLayout`; move it to `post-template` `layout: {type: "grid"}`. `parts/site-header.html` hand-adds an `is-layout-constrained` class, which core already generates.

### PHP

- [ ] **ACF registration runs on the wrong hook.** `lib/acf.php` is included on `after_setup_theme` and calls `acf_add_local_field_group()` / `acf_add_options_page()` immediately. ACF 6.1+ expects `acf/init` and logs `_doing_it_wrong` for early options pages. The options page `menu_slug` is also passed through `esc_html__()`, which makes the slug translatable and breaks the field group's location rule in any non-English locale ([lib/acf.php:53-56](lib/acf.php#L53-L56)).
- [ ] **Unescaped attribute in the Truss header.** `$should_use_logo` is printed into an attribute without `esc_attr()` ([functions.php:454-457](functions.php#L454-L457)). `search-action="/"` is hardcoded and breaks subdirectory installs; use `esc_url( home_url( '/' ) )`.
- [ ] **Missing direct-access guards and unescaped-output triage.** No theme PHP file has a `defined( 'ABSPATH' ) || exit;` guard; add one to `lib/*.php`, `blocks/*/index.php`, `header-plugin.php`, and `footer-plugin.php`. PHPCS reports 8 `EscapeOutput.OutputNotEscaped` findings: fix the real ones (subtitle, Truss attribute above) and give the intentional `do_blocks()`/breadcrumb echoes documented `// phpcs:ignore` annotations so the baseline reads zero.
- [ ] **The last-modified footer prints a raw shortcode when the plugin is inactive.** `ucsc_last_modified()` always runs `do_shortcode( '[last-modified]' )` ([functions.php:481-486](functions.php#L481-L486)). Gate it on `shortcode_exists()`. The same applies to `[site-search]` in [templates/search.html](templates/search.html), which has no fallback when the plugin is off.
- [ ] **The front-end bundle loads on every admin screen.** `ucsc_add_admin_scripts()` enqueues `build/theme.js` (nav, sticky header, sidebar behaviors) on all `admin_enqueue_scripts` ([functions.php:236-247](functions.php#L236-L247)). Nothing in it targets wp-admin. Remove it.
- [ ] **Breadcrumbs fatal if Composer deps are missing.** `ucsc_breadcrumbs_constructor()` calls `Hybrid\Breadcrumbs\Trail` unconditionally ([functions.php:403](functions.php#L403)). That's fine for release zips, but a fresh clone without `composer install` white-screens. Add a `class_exists()` guard, and add a release check that the zip contains `vendor/`.
- [ ] **ACF block styles reference handles that aren't registered.** `acf/breadcrumb-styles` and `acf/main-nav-styles` in `blocks/*/block.json` are not registered anywhere. Remove them or register the handles. `blocks/main-nav/index.php` `echo`es `wp_nav_menu()`, which already echoes and returns `void`.
- [ ] **The custom skip link adds an unlabeled navigation landmark.** The replacement skip link is wrapped in `<div role="navigation">` and assigns an undeclared global, `skipLinkContainer` ([functions.php:572-573](functions.php#L572-L573)). The core removal works on 6.9 (verified), but the replacement creates an extra landmark for one link. Drop the `role` or the custom implementation.

### Performance

- [ ] **Google Fonts loads 7 Roboto weights; markup and CSS use 4.** Only 400, 500, 600, and 700 appear. 100, 300, and 800 are unused, unless Truss needs them, so confirm first. Better: self-host Roboto through `settings.typography.fontFamilies[].fontFace` in theme.json. That removes the third-party request and the `fonts.googleapis.com`/`gstatic` preconnects (and stops sharing visitor IPs with Google), and lets the editor load the font too.
- [ ] **Dashicons loads on every front-end page** ([functions.php:200](functions.php#L200)) for one use, in `wp-blocks/details.css`. Replace that with an inline SVG or `mask-image` and drop the enqueue.
- [ ] **Truss is printed with raw `echo` in `wp_head`, without versioning** ([functions.php:467-477](functions.php#L467-L477)). Use `wp_enqueue_script_module()` (WP 6.5+) and `wp_enqueue_style()` so caching plugins and dependency handling see it, and pin a version instead of tracking the evergreen deploy.

## P3: Cleanup and maintainability

- [ ] **Unused template parts:** `parts/ucsc-logo.html` and `parts/site-title-with-affiliation.html` aren't referenced anywhere. `parts/header.html` and `parts/footer.html` only wrap `site-header`/`site-footer`, adding a layer of indirection. Only `header` and `footer` are declared in `templateParts`, so the other parts appear as "Uncategorized" in the Site Editor.
- [ ] **`index.php` is a stale classic/block hybrid** that would print raw block comments if it were ever used. Reduce it to the standard `// Silence is golden.` stub. Related dead output: `build/index.js` is built but never enqueued, and `package.json` `main` points at it.
- [ ] **Patterns ship site-specific media.** Attachment IDs (`"id":1373`, `"mediaId":52`, …) and image URLs on `sandbox.wordpress.ucsc.edu`, `www-next.ucsc.edu`, and Unsplash download links are hardcoded in about 10 patterns. Inserted patterns show broken images or attach to the wrong media on other sites. Move placeholder images into `images/` and reference them with `get_theme_file_uri()`. Also: `contentSize: "1280px"` is hardcoded in 9 patterns instead of inheriting the global `80rem`, and `featured-image.php`/`featured-video.php` use the unregistered `media` pattern category.
- [ ] **Patterns and strings aren't translatable.** No pattern uses `esc_html_e()`/`esc_attr_e()`. Template HTML strings (404 heading, "News & Events" in `home.html`) can't be translated either; move them into patterns if i18n matters. The same goes for `Last modified:` and its aria-label in `functions.php` and the ACF labels in `lib/acf.php`. JS strings in `main-nav.js`, `cover-block-video-controls.js`, and `wp-blocks/styles.js` are hardcoded English; use `wp.i18n` / `wp_set_script_translations()`.
- [ ] **Pattern metadata inconsistencies.** File name and slug disagree (`card-yellow.php` → `card-yellow-cta`, `post-query-card.php` → `query-loop-card`, `example-page-*` → `*-page`). `post-query-card.php` lists the nonexistent block type `core/featured-image`; it should be `core/post-featured-image`.

- [ ] **Modernize the two ACF blocks.** Add `"apiVersion": 3` to `blocks/breadcrumbs/block.json` and `blocks/main-nav/block.json` (ACF 6.8 on WP 7.1 already registers them as v3, but don't rely on the default), and ship the mobile-toggle JS as a `viewScript` on `main-nav` instead of in the global bundle. The unregistered style handles are covered under PHP above.

Follow-ups from the v3 upgrade: add `layout.wideSize` so "Wide" alignment does something; move link styles into `styles.elements.link` ([issue 346](https://github.com/ucsc/ucsc-2022/issues/346)) and add caption/cite element styles; define the `is-style-ucsc-*` button styles as block style variations; add a default box shadow ([issue 349](https://github.com/ucsc/ucsc-2022/issues/349)); confirm `core/paragraph` should allow custom font sizes.

- [ ] **Dead JS.** `attachEvent` / `createEvent` IE fallbacks in `src/js/utils/events.js`. `state.is_tablet`/`is_mobile`/`*_initialized` are written but never read. The stray `console.log()` in `webpack.config.js`. `verge` and `lodash` can be replaced with `window.innerWidth` and a small debounce; `lodash` is only a transitive dependency and isn't declared in `package.json`. ## Agent visibility and machine readability

_The original 2026-10-12 production audit sampled the homepage and one article (theme v5.2.0, Yoast SEO, Cloudflare). It recorded structured data, preview tags, article landmarks and dates, plus Markdown content negotiation. These observations describe the sample, not every page. The follow-up reviewed theme source, official guidance, and the homepage text. Direct raw-HTML and header requests failed because shell DNS was unavailable. The items marked "proposed" are proposed work, not confirmed production defects._

**Goal:** help agents discover stories, extract accurate facts, and cite stable URLs. JavaScript support varies across crawlers and browser agents. Essential content must remain available in server-rendered HTML. Google requires no special AI markup or AI text file for its AI search features. Standard search practices remain the foundation. Each item names the theme, plugin, editorial, or hosting owner.

- [ ] **Structured data gaps.** _Owner: Yoast settings + site plugin._ The original sample contains `WebSite`, `WebPage`, `Article`, `Person` and `BreadcrumbList`, but no `Organization` or `publisher`. Keep Yoast as the schema owner. Configure the publisher identity and logo. Use `NewsArticle` for news posts, with accurate authors, images, `datePublished` and `dateModified`. Google also supports `Article`. Make sure that the graph matches visible content. A 404 at `/news-sitemap.xml` does not establish that no news sitemap exists elsewhere. Audit sitemap discovery before adding a news sitemap through Yoast News SEO or another compatible plugin. A news sitemap aids recent-news discovery, not guaranteed inclusion.
- [ ] **Descriptions and preview tags.** _Owner: Yoast settings._ No page checked has a `meta description`, even though articles have excerpts; set Yoast's description template to use the excerpt. The homepage's preview tags are weak: `og:title` is just "UC Santa Cruz", `og:description` is "Explore stories by topic", and there's no `og:image`.
- [ ] **Global header and footer invisible without JavaScript.** _Owner: Truss + theme._ Confirmed on production: `<trss-ucsc-header>` and `<trss-ucsc-footer>` arrive empty, so crawlers that don't run JS never see the campus-wide navigation, search or footer links. Options: pre-render Truss (Stencil supports declarative shadow DOM), or have the theme print plain fallback links inside the tags. Would also help [issue 332](https://github.com/ucsc/ucsc-2022/issues/332) (layout shift).
- [ ] **Dates agents can read.** _Owner: theme + `ucsc-custom-functionality`._ **Theme:** the "Last modified" footer (`ucsc_last_modified()` in `functions.php`) is plain text; wrap it in `<time datetime="…">`. **Plugin:** the homepage's featured news cards show no dates and have no `<time>` markup, so an agent reading the homepage can't tell which stories are new (article pages and "Related stories" cards do have dates). **Also:** the HTTP `Last-Modified` header on the checked article said Oct 12 while its real modified date was Oct 8, so the header appears to reflect when the page was regenerated, not edited.
- [ ] **Markdown version drops the title, date and byline.** _Owner: `ucsc-custom-functionality` + Cloudflare._ Requesting a page with `Accept: text/markdown` returns clean Markdown (Cloudflare's converter, cached at the edge). That's a real advantage for agents, but on articles the `<h1>`, date and author are missing from the body; only the title survives, in the front matter. They all sit in the post header block's `<header>` element, which the converter appears to skip. Test whether changing that block's markup, or a Cloudflare setting, keeps them. "Related stories" also comes through as raw HTML (`<h3>` tags inside link text).
- [ ] **Image alt text.** _Owner: `ucsc-custom-functionality`, `ucsc-blocks`._ The six outlet logos in the homepage "Media coverage" section have no `alt` attribute at all, so agents and screen readers get nothing or a file name; use the outlet name. On the local site, event images from the `ucsc-blocks` events block had empty `alt` text; not checked on production.
- [ ] **Crawler access policy.** _Owner: `ucsc-primary-sites` (`class-robots-txt.php`) + hosting._ The original audit recorded `Crawl-delay: 120` for listed AI bots. Support for this directive varies, so it is not an enforced rate limit. Separate search discovery, training, and user-requested access in the university policy. OpenAI documents independent controls for OAI-SearchBot and GPTBot. ChatGPT-User requests can fall outside robots.txt rules. Googlebot controls Google's AI search access. Google-Extended controls other uses. Make sure that robots rules, `noindex`, snippet restrictions, and Cloudflare settings agree with the approved policy. A spoofed user agent does not establish access for a verified bot. Use provider IP verification and hosting logs for access evidence.
- [ ] **Optional agent interfaces (evaluate; P3).** _Owner: site plugin._ The original audit recorded a 404 for `llms.txt`. Treat this file as an experiment with a named consumer and measurable use. Google requires no AI text file. Keep any index generated from canonical public content. Evaluate WordPress Abilities API actions separately for staff tools, with endpoint permissions and authentication defined first. Public discovery does not require an agent API.
- [ ] **Article semantics and content boundaries (proposed; P1).** _Owner: theme + news template plugin._ `templates/single.html` has `<main>`, a title, date and byline, but no `<article>` wrapper around the story. Put the title, byline, dates and body inside one article region. Keep comments and related stories outside that region. Audit heading levels in templates and patterns. The nested-`<main>` defect is tracked under P1 above. Audit database template overrides on news.ucsc.edu before changing files.
- [ ] **Crawlable archives, search and feeds (proposed; P2).** _Owner: theme + site plugins._ Preserve the title links, dates and numbered pagination already in `parts/post-query.html`. Make sure that topic archives and older stories remain reachable through ordinary `<a href>` links without JavaScript. `templates/search.html` depends on `[site-search]`. Audit its provider and add a usable search form and results fallback where necessary. Make RSS feeds discoverable through visible links and feed metadata. Audit canonical URLs, redirects and sitemap coverage in the SEO plugin. Avoid an unlimited crawl space from search filters.

### Acceptance checks

1. **Content extraction:** An unauthenticated HTML request contains the story title, summary where available, byline, publication date, and full body. One `<main>` contains the page content. One `<article>` identifies the story. Related content and comments remain distinct.
2. **Dates and attribution:** Visible dates use `<time datetime>` with ISO 8601 values. Publication and meaningful update dates have separate labels. Each visible author appears in Yoast's graph. Theme changes must not reset editorial dates. On archives, omit a post-specific modification date unless its meaning is explicit.
3. **Discovery:** A JavaScript-disabled visitor can reach a topic, its second archive page, and an older story through links. The final story URL returns HTTP 200 and has one canonical target. Sitemap URLs match canonical URLs. A news sitemap includes news metadata only for articles from the last two days.
4. **Extraction formats:** HTML and Markdown preserve the same story facts and links. Title, byline and dates survive conversion (see the Markdown item). Each request receives the correct content type after cache hits in either request order.
5. **Schema and controls:** The rendered graph passes syntax and applicable rich-result checks without conflicting theme schema. Navigation and search work with a keyboard. Controls have accessible names. Header fallback links remain useful before Truss loads. Fallback markup must work with Truss hydration and must not duplicate accessible controls.
6. **Access evidence:** Approved search crawlers receive content without a login or bot challenge. Hosting logs establish verified bot access. A local request with a copied user agent is only a preliminary diagnostic.

### Guidance and scope

- [Google: AI features and your website](https://developers.google.com/search/docs/appearance/ai-features) — established search requirements, visible text, internal links, snippet controls, and reporting limits.
- [Google: Article structured data](https://developers.google.com/search/docs/appearance/structured-data/article) — supported article types, editorial dates, images, and author identity.
- [Google: Crawlable links](https://developers.google.com/search/docs/crawling-indexing/links-crawlable) and [news sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/news-sitemap) — discovery through links and recent-news metadata.
- [OpenAI: crawler controls](https://developers.openai.com/api/docs/bots) — separate search, training, and user-requested access.
- [Cloudflare: Markdown for Agents](https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents/) — content negotiation and cache separation.

**Theme boundary:** presentation, semantics, accessible controls, fallback content, and rendered-output checks belong here. Publisher schema, canonical URLs, feeds and sitemaps belong in persistent site plugins. Bot access belongs in hosting and university policy. Editorial summaries and source links need newsroom ownership. Prioritize the Truss fallback, readable dates, article semantics, release checks, and operable controls for theme work; pair them with the breadcrumb schema, nav accessibility, and performance items. Evaluate `llms.txt` and agent APIs after the public content works reliably.
